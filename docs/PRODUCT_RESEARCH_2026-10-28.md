# Product pain-point research — 2026-10-28

This is a focused evidence log, not a claim that every Mealie or Home Assistant user shares the same problem. Upstream issues and discussions show individual reports; decisions below are design responses to those reports and to the project’s own code/QA findings.

## Research-driven implementation principles

1. Preserve the current cooking step and surrounding context; do not replace instructions with a step-number-only screen.
2. Keep images authenticated or absent. Never construct unauthenticated private Mealie media URLs from card code.
3. Show provider capability and result truncation where the user can act on them.
4. Keep fallback behavior read-only and explicit. Never downgrade a write request to an unrelated provider.
5. Treat allergy, dietary, nutrition, and AI results conservatively. Explain uncertainty and require human confirmation.
6. Test setup and recovery, not only the happy-path recipe grid: missing integration, unavailable service, no recipe results, partial results, stale resource cache, and disabled writes.

## Evidence limitations

Public issue pages can close or change over time; their reports are specific cases, not prevalence data. Competitor pages document their own feature requirements, not product quality. Live Home Assistant was not available during this review. Mealie API and HA action behavior must be verified against the exact supported versions before stable release.
